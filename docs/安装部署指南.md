本文覆盖三部分：

1. **本地执行流程**（开发 / 日常使用）
2. **远程部署流程**（Relay 公网中转）
3. **本机 CLI 安装**（Claude / Cursor Agent / Codex / WorkBuddy；含 `scripts/install-cli` 一键脚本）

相关文档：[服务启动指南](./服务启动指南.md) · [CLI 注册表](../agent/src/tools/README.md) · [DNS](../relay/deploy/DNS.md)

## 架构速览

```text
手机 App  ──ws──►  Relay（公网 Nginx → Node:8787）  ◄──ws──  PC Agent（Windows）
                                                              │
                                                    Claude / Codex / Cursor Agent …
```

| 组件 | 职责 | 典型位置 |
|------|------|----------|
| `relay` | 配对、JWT、任务转发与 SQLite 历史 | 云服务器 |
| `agent` | 连接 Relay，在本机 spawn CLI | Windows PC |
| `app` | Flutter 手机遥控端 | Android |
| `shared/protocol` | WebSocket 协议（Relay/Agent 共用） | 随仓库构建 |

生产默认地址：

- WebSocket：`ws://relay.example.com/ws`
- 健康检查：`http://relay.example.com/health`

## 1. 本地执行流程

适用于：日常遥控、本机调试。生产环境下 **Relay 已在云端常驻**，本机一般只跑 **Agent + App**。

### 1.1 环境要求

| 软件 | 版本建议 | 用途 |
|------|----------|------|
| Node.js | 20+（建议 LTS） | Relay / Agent |
| npm | 随 Node | workspace 构建 |
| Flutter | 3.x（与 `app/pubspec.yaml` SDK 匹配） | 打包 / 调试 App |
| Windows | 10/11 | Agent 与各 CLI |
| Android | 支持 USB 调试 | 安装 APK |

### 1.2 首次克隆与构建

```powershell
cd D:\wamp64_332\www\grokbot   # 换成你的仓库路径
npm install
npm run build                  # 全量：protocol → relay → agent
```

#### 改代码后怎么构建

根目录 `package.json` 的 `build` 会串起三个 workspace。日常改 PC Agent 时常用分项命令：

| 改动范围 | 命令 |
|----------|------|
| 仅 Agent（`agent/src`、skills、mcp 等） | `npm run build -w agent` |
| 协议 `shared/protocol` | 先 `npm run build -w shared/protocol`，再 `npm run build -w agent`（部署 Relay 时还要 `npm run build -w relay`） |
| 仅 Relay | `npm run build -w relay`（通常先编过 protocol） |
| 不确定 / 首次 | `npm run build` |

```powershell
# 示例：协议 + Agent
npm run build -w shared/protocol
npm run build -w agent
npm run agent          # 或 npm run dev:agent（tsx 热重载，开发时可跳过先 build）
```

可选：复制环境变量模板（勿把真实密钥提交 Git）。

```powershell
copy agent\.env.example agent\.env
# 按需填写 GROK_* 等；Claude/Codex/Cursor 通常用各自登录态，不必写在 .env
```

### 1.3 配置 PC Agent

编辑 [`agent/agent.config.json`](../agent/agent.config.json)（路径、工作区按本机改）：

| 字段 | 说明 |
|------|------|
| `relayUrl` | 默认 `ws://relay.example.com/ws`；纯本地联调用 `ws://127.0.0.1:8787/ws` |
| `workspaces` | 手机可选的本机**工作空间**白名单（详见下一节） |
| `tools.claude` | Claude Code 可执行文件绝对路径 |
| `tools.codex` | Codex CLI 绝对路径 |
| `tools.agent` | Cursor Agent（`agent.ps1` / `agent.cmd`）路径 |
| `autoApprove` | `true` 时跳过危险操作二次确认（手机遥控常用） |
| `fileOffer` | 文件推送到手机的配置（详见 1.9） |

配对成功后会生成 **`agent/agent.config.local.json`**（含 token，勿提交）。

### 1.4 工作空间（workspaces）

工作空间决定 **CLI 在本机哪个目录里执行**（Claude / Codex / Cursor Agent 的 cwd）。  
手机端只能选择 Agent 配置里声明过的目录，相当于路径白名单，避免任务跑到任意磁盘位置。

#### 配置位置与字段

在 [`agent/agent.config.json`](../agent/agent.config.json) 的 `workspaces` 数组中配置，每项三个字段：

| 字段 | 说明 |
|------|------|
| `id` | 稳定标识（英文/数字/`-`/`_`），任务报文用这个 id，**改名不影响已有会话时尽量别改 id** |
| `name` | 手机上显示的名称（可中文） |
| `path` | 本机绝对路径；Windows 可用 `D:\\proj\\foo` 或 `D:/proj/foo` |

示例：

```json
"workspaces": [
  {
    "id": "default",
    "name": "默认项目",
    "path": "D:\\projects\\my-app"
  },
  {
    "id": "docs",
    "name": "文档仓",
    "path": "D:\\projects\\docs"
  }
]
```

#### 手机端怎么用

1. Agent 连上 Relay 后，会通过 `agent.status` 把工作空间列表推给 App  
2. 输入框上方工具条里，当配置了 **2 个及以上** 工作空间时，会显示当前工作区名称；点一下即可切换  
3. 只有 1 个工作空间时不显示切换入口（默认用这一项）  
4. **每个会话各自记住**所选工作空间；发任务时带上对应 `workspaceId`

#### 生效与校验

- 修改 `workspaces` 后需 **重启 Agent**（`npm run agent`），手机会在下次 `agent.status`（约数秒内）刷新列表  
- 路径必须在本机真实存在，否则该次任务失败，Agent 报错形如：`工作区路径不存在: …`  
- 任务里的 `workspaceId` 必须能在配置中找到，否则：`未知工作区: …`  
- 部分工具还会用白名单校验：目标路径不能逃出当前工作空间根目录  

#### 建议

- 第一个条目作为日常默认（新会话常落在列表里仍有效的那一项）  
- 按「一个 git 仓库 / 一个独立项目」拆空间，避免把整个磁盘根目录配进去  
- `id` 一经对外使用尽量固定；只想改手机显示文案时改 `name` 即可

### 1.9 文件下发到手机（fileOffer）

任务成功结束后，Agent 自动扫描工作区**新产生的匹配文件**（默认任意层级 `.apk`）上传到 Relay，手机聊天里出现文件卡片，点击下载（断点续传、sha256 校验）后可直接打开；APK 会拉起系统安装器（Android 8+ 需用户手动确认安装，系统限制）。

`agent.config.json` 可调：

| 字段 | 默认 | 说明 |
|------|------|------|
| `fileOffer.enabled` | `true` | 关掉则只保留「取文件」工具手动推送 |
| `fileOffer.patterns` | `["**/*.apk"]` | 相对路径匹配模式，支持 `*` 与 `**` 前缀 |
| `fileOffer.excludeDirs` | `node_modules` 等 | 扫描时跳过的目录名 |
| `fileOffer.maxFiles` | `3` | 单次任务最多推送几个文件（新→旧取前 N） |
| `fileOffer.maxFileMb` | `500` | 单文件大小上限 |

手动推送任意文件：App 工具条选「取文件」，输入工作区相对路径（如 `docs\架构.png`）发送即可。

Relay 侧环境变量（服务器 `.env`）：`FILES_DIR`（默认 `relay/data/files`）、`FILES_TTL_HOURS`（默认 24）、`MAX_FILE_MB`（默认 500）。**旧版 Relay 没有 `/files` 端点，需按 §2.3 重新部署。**

## 2. 远程部署流程（Relay）

Agent 与 App **不部署到服务器**；服务器只跑 **Relay + Nginx**。

### 2.1 服务器与域名（现状）

| 项 | 值 |
|----|-----|
| 主机 | `你的服务器IP` |
| 系统 | Alibaba Cloud Linux 3 / 同类 Linux |
| 应用目录 | `/opt/grokbot-relay` |
| systemd | `grokbot-relay` |
| 域名 | `relay.example.com` → A 记录指向服务器 IP |
| 协议 | 明文 `ws://`（80 → 本机 8787），需安全组放行 **80** |

DNS 与安全组详见 [`relay/deploy/DNS.md`](../relay/deploy/DNS.md)。

### 2.2 首次部署（本机一键上传）

依赖：本机已 `npm install`、Python3 + `paramiko`（脚本可自动 pip）。

```powershell
cd D:\wamp64_332\www\grokbot

$env:GROKBOT_SSH_HOST='你的服务器IP'
$env:GROKBOT_SSH_USER='root'
$env:GROKBOT_SSH_PASS='你的SSH密码'          # 勿写入仓库
$env:GROKBOT_DOMAIN='relay.example.com'

python relay/deploy/upload_deploy.py
```

脚本会：

1. 本地构建 `shared/protocol`、`relay`
2. 打包 `dist` + protocol vendor + `remote-setup.sh`
3. 上传到 `/opt/grokbot-relay`
4. 执行 `remote-setup.sh`（Node 依赖、systemd、Nginx、可选证书相关步骤）
5. 打印 `ws://域名/ws` 与 health 地址

### 2.3 日常更新代码（推荐）

协议或 Relay 有改动时：

```powershell
cd D:\wamp64_332\www\grokbot
# 同上设置 GROKBOT_SSH_* / GROKBOT_DOMAIN
python relay/deploy/upload_deploy.py --sync
```

`--sync`：同步协议 dist、**重启** `grokbot-relay` 并检查 health（比完整 remote-setup 更快）。

### 2.4 SSH 运维常用命令

```bash
ssh root@你的服务器IP

systemctl status grokbot-relay
systemctl restart grokbot-relay
journalctl -u grokbot-relay -f

curl -sS http://127.0.0.1:8787/health
# 或外网：curl -sS http://relay.example.com/health

# 环境变量（JWT_SECRET、RELAY_PUBLIC_URL 等）
cat /opt/grokbot-relay/.env

nginx -t && systemctl reload nginx
```

### 2.5 服务器 `.env` 要点

参考 [`relay/.env.example`](../relay/.env.example)：

```env
PORT=8787
HOST=0.0.0.0
JWT_SECRET=请换成足够长的随机串
RELAY_PUBLIC_URL=ws://relay.example.com/ws
# 文件通道（可选，不填用默认值）
# FILES_DIR=/opt/grokbot-relay/data/files
# FILES_TTL_HOURS=24
# MAX_FILE_MB=500
```

更换 `JWT_SECRET` 后，旧 token 全部失效：需清空 Agent `agent.config.local.json` 中的 `token`，手机重新配对。

文件通道会在 `FILES_DIR` 落盘 APK 等大文件，注意服务器磁盘；过期文件每 10 分钟自动清理。

### 2.6 远程部署验收

- [ ] `systemctl is-active grokbot-relay` → `active`
- [ ] `curl http://域名/health` → `{"ok":true,...}`
- [ ] 本机 Agent 能连上并保持「已连接 Relay」
- [ ] 手机配对成功并下发任务
- [ ] `curl -i http://域名/files/xxx`（不带 token）→ 404（文件通道已生效）

## 3. 本机 CLI 安装文档

Agent 通过 `agent.config.json` → `tools.*` 调用本机命令。主菜单默认：**Claude / Cursor Agent / Codex / WorkBuddy**（以及「自动」→ Claude）。

### 推荐：一键安装脚本（Windows）

仓库已提供脚本，会调用各官方安装器、探测路径并写回 `agent.config.json`：

```powershell
cd D:\wamp64_332\www\grokbot   # 换成你的仓库路径

# 全部
powershell -ExecutionPolicy Bypass -File scripts\install-cli\install-all.ps1

# 或单独安装
powershell -ExecutionPolicy Bypass -File scripts\install-cli\install-claude.ps1
powershell -ExecutionPolicy Bypass -File scripts\install-cli\install-cursor-agent.ps1
powershell -ExecutionPolicy Bypass -File scripts\install-cli\install-codex.ps1
powershell -ExecutionPolicy Bypass -File scripts\install-cli\install-workbuddy.ps1
```

说明见 [`scripts/install-cli/README.md`](../scripts/install-cli/README.md)。  
**登录需人工**：装完后本机分别执行 `claude` / `agent login` / `codex`；WorkBuddy 在首次任务弹出的 Chrome 里登录一次。

也可手工安装后把 **绝对路径** 写入配置，例如：

```json
"tools": {
  "claude": "C:\\Users\\你的用户\\.local\\bin\\claude.exe",
  "agent": "C:\\Users\\你的用户\\AppData\\Local\\cursor-agent\\agent.ps1",
  "codex": "C:\\Users\\你的用户\\AppData\\Local\\Programs\\OpenAI\\Codex\\bin\\codex.exe",
  "chrome": "C:\\Program Files (x86)\\Google\\Chrome\\Application\\chrome.exe",
  "workbuddyUrl": "https://workbuddy.cn/app",
  "workbuddyCdpPort": "9333"
}
```

只改 `agent.config.json` 里的路径：**重启** `npm run agent` 即可，不必重新 build。  
改了 `agent/src` 等 TypeScript：先 `npm run build -w agent`（协议有变则先 `npm run build -w shared/protocol`），再重启；开发可用 `npm run dev:agent`。

**WorkBuddy**：网页遥控，无独立安装包。准备环境：

```powershell
powershell -ExecutionPolicy Bypass -File scripts\install-cli\install-workbuddy.ps1
```

会检查/安装 Chrome、确保 Claude，并写入 `tools.chrome` / `workbuddyUrl` / `workbuddyCdpPort`。  
选该工具时 Agent 用专用 Chrome 配置（`agent/data/workbuddy-chrome-profile`）打开 `workbuddy.cn/app`；请在弹出窗口 **人工登录一次**，之后手机自然语言下指令，由 Claude 规划点击/输入。

## 4. 常见问题（部署相关）

| 现象 | 处理 |
|------|------|
| App 配对失败 | Relay 必须是 `ws://`；DNS/安全组 80；Agent 是否在线 |
| Agent 反复断开 | 删 `agent.config.local.json` 的 `token`，`npm run agent:pair` 重配 |
| Claude/Codex/Cursor 无响应 | 本机 CLI 能否单独跑通；路径是否写进 config；看 Agent 控制台报错 |
| Codex 一直无输出 | 确认已更新含 stdin ignore 的 Agent；本机用 `codex exec` 验证登录 |
| 提示未知工作区 / 路径不存在 | 检查 `workspaces[].id` 与 App 所选是否一致；`path` 是否为本机真实目录；改完后重启 Agent |
| App 看不到工作区切换 | 至少配置 2 个 `workspaces`；确认 Agent 已上线并推送了 `agent.status` |
| 远程更新后 App 异常 | 协议变更需部署 Relay；必要时重装匹配版本 APK |
| ADB `device offline` | 重插 USB、重新授权调试、`adb kill-server` 后再 `adb devices` |
